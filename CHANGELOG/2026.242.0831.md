# 2026.242.0831 — feat: run the web console and plugin runner on a container venue too

## Summary

`punktfunk-web` and `punktfunk-scripting` were **packaged-only** services, so a container
venue installed both packages, advertised the console on `https+insecure:47992`, and started
neither. Only `punktfunk-host` had a container form. The candy was promising a surface the
venue never delivered.

Adds the two missing wrappers, mirroring the **packaged units** rather than guessing at
their behaviour — the units were read out of the published packages:

- `web-init.sh` runs first as the readiness gate. The unit's own comments are explicit that
  `After=punktfunk-host.service` is *not* one, because the host is `Type=simple` and systemd
  calls it started the instant it is spawned, seconds before the token and identity cert
  land.
- The server then gets `PUNKTFUNK_MGMT_TOKEN`, the optional web password, `PORT`/`HOST` and
  the TLS pair from the same `KEY=VALUE` files the unit's `EnvironmentFile=` lines name — so
  there is one source of truth rather than values duplicated into the wrapper.
- The TLS paths deliberately name the **legacy** pair, because the server prefers the native
  sibling when it exists and that choice lives in the server, not the launcher.
- The scripting runner waits for the same token rather than trusting supervisord start order.

Closes opencharly/layer-punktfunk#4.

## How tested

**A committed gate, wired into CI** (`test/wrappers.sh`, new step in `deploy.yml`). It drives
the **shipped scripts** — not copies — against stubs, which is why the wrappers now take
`PUNKTFUNK_WEB_SERVER_BIN` / `PUNKTFUNK_SCRIPTING_BIN` / `PUNKTFUNK_WEB_INIT` /
`PUNKTFUNK_READY_TIMEOUT` overrides with the packaged paths as defaults:

```
  PASS  web: fails closed with a named cause when mgmt-token never appears
  PASS  web: runs web-init.sh (the readiness gate) before the server
  PASS  web: sources mgmt-token (KEY=VALUE env-file form)
  PASS  web: sources the optional web-password
  PASS  web: sets the unit's PORT/HOST
  PASS  web: enables TLS (PUNKTFUNK_UI_SECURE)
  PASS  web: points at the legacy cert pair the server falls back from
  PASS  scripting: fails closed when the host never starts
  PASS  scripting: execs the runner once the host's token exists

all wrapper checks passed
```

**It catches breakage** — removing the `PUNKTFUNK_UI_SECURE` export:

```
  FAIL  web: PUNKTFUNK_UI_SECURE not set: TOKEN=deadbeef PASS=hunter2 PORT=47992 … SECURE=
1 wrapper check(s) FAILED
```

**Plus a runtime check in the candy** (`punktfunk-web-console-live`) asserting the console
actually answers on 47992, so the advertised port stops being an unverified promise. It is
venue-neutral: on a container the wrapper serves it, on systemd the packaged unit does.

```
$ charly box validate
VALIDATE_EXIT=0
```
